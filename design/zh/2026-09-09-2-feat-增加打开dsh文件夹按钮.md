# 2026-09-09-2-feat-增加打开dsh文件夹按钮

## 直接原因

用户希望复用设置页右上角「打开配置文件」的区域，在旁边增加一个「打开 .dsh 文件夹」按钮，一键在系统文件管理器中打开 dsh 数据目录。

## 解决方案

「打开配置文件」是 `ui-settings-general` 注册在 `settings.action` 槽（list 槽，id `open-document`，order 0）的条目；list 槽支持多个条目按 order 排序并排渲染，因此本插件注册第二个条目（id `open-dsh-folder`，order 1）即可在旁边显示。

打开本地文件夹是特权操作，浏览器无权执行，必须由 Host 完成。dsh 网关支持 SRC 反射：任何注册进 ctx 的 `TypertRemoteService` 子类（带 `typertRemote` binding 与 `@Remote` 方法）都会被网关识别并暴露端点，无需 typert 生成器产物。本插件 Host 侧新增 `OpenDshFolderService`，命名空间 `uiFortifier`，暴露 `openDshFolder` 端点：

- `resolveDshHome()` 解析 `.dsh` 目录（`$DSH_HOME` → `~/.dsh`）；
- `canOpenNativePath()` 可打开时调用 `openNativePath(home, signal)` 打开目录，返回 `{ opened: true, path }`；
- 无原生打开器（如无显示服务器的 Linux）时返回 `{ opened: false, path }`，按钮位置以路径文本展示。

客户端侧新模块 `open-dsh-folder`：注册 `settings.action` 槽新条目，按钮点击通过 `ctx.connection.rpc.call('/api', 'uiFortifier/openDshFolder', { args: {} })` 调用端点。安全边界与「打开配置文件」一致：仅 `connection.isLoopback` 为真时注册按钮，远程部署不显示、请求也会被连接层认证拦截。

功能开关沿用 `ui-fortifier` settings 命名空间：`open-dsh-folder` 配置项默认 true，可在设置页关闭。

## 思路

- 按钮位置：直接复用现有 `settings.action` list 槽，避免改动 `ui-settings-general` 的声明。
- 能力边界：整个功能在插件内实现，Host 侧通过 SRC 反射暴露端点，不改 dsh 本体任何文件，符合 dsh.md 的协作规则。
- 安全：与「打开配置文件」共用回环限制与连接认证，远程部署降级为不显示，不产生不可用的按钮。
- 复用现有机制：模块开关、locale 文案、`connection.rpc.call` 低层通道均复用既有设施，少量新代码。
