# 2026-09-12-2-feat-会话标题栏复制会话ID

## 直接原因

需要拿到当前会话 ID，但界面没有给出途径。核对了会话标题栏：标题区是面包屑导航，只有 `ancestry.length === 0`（会话不在侧栏列表中）时才回退渲染原始 `sessionId`，正常情况显示的是会话标题；URL 不带会话 ID；标题栏也没有复制入口。因此需要一个就地可取会话 ID 的入口。

目标位置原本希望是会话标题栏三点菜单（「下载会话日志」所在菜单）内的一项，但该菜单不可扩展：它由 `session-log-export` 拥有（`packages/session-query/session-log-export/src/client/HeaderAction.tsx`），菜单项是硬编码数组，而 `Menu` 原语的 `items` 是普通 prop，没有菜单项插槽。

## 解决方案

新增 `session-id-copy` 功能模块，注册进 `conversation.session.header.utilities`——官方为会话标题栏「右对齐工具组」声明的 `list` 槽（追加式）。该槽现有两个占用者正是标题栏右侧的「在本地打开」按钮与三点菜单，因此新按钮与它们并排显示。

- 按钮为 28px 高胶囊，内含井号与复制两个字形并排，点击即在标题栏原地复制 Session ID。
- 井号字形为组件内联 SVG：官方图标库没有标识符类图标，单用复制图标无法表达与会话 ID 的关系。
- 悬停/聚焦时经 `Tooltip` 原语显示 `Session ID: {id}`，会话 ID 直接可见（不必先复制再粘贴）。复制成功后提示改为「已复制」。
- 复制走 `writeClipboard`（ui-primitives 提供，优先异步 Clipboard API、缺失时回退 `execCommand`），成功后图标换成对勾约 1 秒，与官方 `MessageIconActions` 的反馈方式一致。
- `order: -20` 使按钮排在该槽最左。该槽按 order 升序排列，现有占用者为 `open-in-app`（-10）与 `session-log-download`（默认 0）。
- 会话 ID 取自槽位 owner 参数（该槽 `scope: 'session'`，组件经 `PropsRuntime` 直接拿到 `sessionId`）。
- 可经设置页开关关闭，默认开启，走既有模块控制机制（关闭即卸载注册）。

## 思路

- 不改 dsh 仓往三点菜单里加项：那需要修改 `session-log-export` 的源码，而 harness 源码会被 dsh 升级覆盖（此前适配 dsh 0.1.5 的调用方上下文变化即为例证），也超出插件仓的范围。
- 选 `list` 槽而非 `conversation.session.header.corner`（`single` 槽，已被 ui-sidebar-right 占用）：追加式槽位不替换任何官方声明，与插件在 `conversation.input.right` 上的既有做法一致。
- 复制反馈照抄官方既有模式（短对勾换图标 + 反馈窗口内忽略重复点击 + 卸载时清定时器），不引入新的提示组件。
- 井号字形内联而非取用官方图标：官方 75 个图标中没有标识符类字形，而插件不能引用其他插件的组件；内联描边是本插件既有做法。
- 提示用 `Tooltip` 原语而非原生 `title`：原语在悬停与键盘聚焦时都显示，且气泡可被主题令牌着色；同时不再设原生 `title`，避免两套提示叠加。
