# 2026-09-11-3-chore-移除空的不变量伴生入口

## 直接原因

`verify-package-invariants` 对本包报两条：

```
package.json: @deepseek-ai/dsh-invariants must not be a peerDependency under this package dependency policy
src/invariant.ts: empty install function is unnecessary; omit the companion and its publication wiring
```

本包是纯插槽表面（注册插槽、一个 settings 命名空间、一个 Remote 端点，只读官方共享 store），没有自有事件流或可变状态，不存在可能独立产生分歧的观察。harness 的 `2026-08-28-omit-unneeded-invariant-companions` 决策已反转早期「每个包都发布 `./invariant`」的要求：无符合条件的关系时省略伴生入口，并拒绝空 installer，改由包 README 记录省略原因。本包的 `src/invariant.ts` 是 08-31 搭建时按旧规则留下的空壳（`const install: InvariantInstaller = () => {}`）。

## 解决方案

删除 `src/invariant.ts` 及全部发布接线：

- `src/invariant.ts`：删除（空 installer）。
- [package.json](../../package.json)：删除 `exports["./invariant"]`、`files` 中的 `lib/invariant.js`、`dsh-invariants` 的 peer 与 dev 依赖。
- [tsconfig.host.json](../../tsconfig.host.json)、[tsconfig.client.json](../../tsconfig.client.json)：删除 `runtime-diagnostics/invariants` 项目引用。
- [tsdown.config.ts](../../tsdown.config.ts)：构建入口去掉 `lib/types/invariant.js`。
- [README.md](../../README.md)、[README.zh.md](../../README.zh.md)：记录不发布伴生入口及其原因（英文句满足门禁对省略原因的要求）。

## 思路

- 依 harness 的判定标准：只有包能比较「可能独立产生分歧的观察」时才发布伴生入口（跨事件生命周期/顺序/身份/配对协议；事件与权威可变状态；多生产方组装输出；被下游折叠或消费的持久数据）。否则交给类型、加载或单元测试。本包四条均不满足。
- 门禁对「省略」有硬要求：导出、发布项、构建接线与项目引用都必须同步移除，且英文 README 必须写明原因，否则会换成另一条报错。
- 后续若引入自有可变关系或被消费的事件协议（如自持跨入口共享状态、自定义事件协议、下游读取的持久数据），需重新审视本结论、更新 README 并添加带真实断言的伴生入口。

## 涉及文件

- `src/invariant.ts`：删除。
- [package.json](../../package.json)、[tsconfig.host.json](../../tsconfig.host.json)、[tsconfig.client.json](../../tsconfig.client.json)、[tsdown.config.ts](../../tsdown.config.ts)：移除发布接线与项目引用。
- [README.md](../../README.md)、[README.zh.md](../../README.zh.md)：记录省略原因。
