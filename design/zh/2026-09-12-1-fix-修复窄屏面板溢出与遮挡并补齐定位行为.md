# 2026-09-12-1-fix-修复窄屏面板溢出与遮挡并补齐定位行为

## 直接原因

手机屏幕上打开级联模型选择面板时出现三个问题：

1. **面板比屏幕还宽**：`.menu` 的 `min-width: 420px` 是绝对值，超过手机屏宽。CSS 中 `min-width` 优先于 `max-width`，所以已有的 `max-width: min(520px, calc(100vw - 32px))` 挡不住它。
2. **面板被左侧对话列表遮挡**：面板是 `position: absolute`，包含块为输入框卡片，而 `.centerCol`（`AppFrame.module.css`）与 `.conversationRoot[data-phase='active']`（`ConversationRoot.module.css`）都有 `overflow: hidden`，超出列边界的部分被裁掉，视觉上表现为被侧栏挡住。抬高 `z-index` 对此无效——这是裁切而非层叠。
3. **模型名过长被截断**：`.modelName` 同时声明 `overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`，长模型 id 只显示省略号。

同时面板的定位行为不理想：左边缘对齐触发器，且缺少展开时的滚动定位。

## 解决方案

### 面板改为 portal + fixed（问题 1、2）

`ModelPicker.module.css`：`.menu` 由 `absolute` 改为 `position: fixed`，`z-index` 由 1000 提到 1100；`right` / `bottom` / `transform: translateX(-72px)` 全部移除——portal 到 body 后，列的 overflow 裁切与侧栏都不再作用于它，原先为避开「回到最底部」悬浮按钮而做的左移也已无必要。

`ModelPicker.tsx`：面板经 `createPortal` 挂到 `document.body`。因面板离开了 `rootRef` 子树，「点击外部关闭」的判断须同时检查 `menuRef`，否则点击面板内部会被误判为外部而关闭。

### 宽度下限跟随视口（问题 1）

```css
min-width: min(420px, calc(100vw - 32px));
```

宽屏仍用 420px 保证两列可读，窄屏则收进视口内。

### 模型名换行（问题 3）

`.modelName` 移除三条截断规则，改为 `overflow-wrap: anywhere`。`anywhere` 是必需的补充：模型 id 常为无空格长串，仅去掉 `nowrap` 在无断点处仍会溢出。

### 右对齐 + 视口钳位（定位）

面板右边缘对齐触发器右边缘，仅当这样越出视口时才平移回边界内。因官方 `useAnchoredPosition` 固定从触发器**左**边缘定位且无对齐选项，本插件本地实现了 `useRightAlignedMenuPosition`：右对齐算术 `left = rect.right - width`，保留官方的钳位、`scroll`(capture)/`resize` 重算，并额外用 `ResizeObserver` 跟随面板自身尺寸变化。

未定位态采用 `MEASURE_STYLE`（`visibility: hidden` + 原点），使首帧量取到真实尺寸且不会闪现在原点——与官方 `ModelSelect.tsx` 同法。视口边距取 12，与官方 `MARGIN = 12` 一致。

### 展开时定位到当前选择，切换提供商时重置

- 展开后把当前提供商（左列）与当前模型（右列）滚进视野，用 `useLayoutEffect` 在绘制前完成，面板不会先停在顶部再跳；`positionedRef` 保证每次展开只定位一次，之后用户手动滚动不会被拽回。
- 切换提供商时模型列 `scrollTop` 归零。容器在切换间复用同一 DOM 节点，React 不会自动重置。
- 切回**当前模型所属**提供商时改为定位到当前模型：该提供商的模型列表若非活动列，记 `pendingCurrentScrollRef` 交给定位效果在渲染后处理（该分支须排在 `positionedRef` 守卫之前，否则永远进不去）；若已是活动列则当场滚动——此时列表内容不变、效果不会重跑，把待定标志留着会让状态悬空到下一次无关重渲染才生效。

## 思路

- 面板的遮挡问题与层叠无关，根因是祖先 `overflow: hidden` 裁切，官方 `ModelSelect` 的 `.menu` 注释亦点明「portaled to body ... so the sidebar and the columns' overflow clips cannot crop it」。故采用同一手法。
- 断言「portal 不会污染全局样式」的依据：CSS Modules 输出带 hash 前缀的逐条选择器，portal 只改元素位置不改选择器；主题层的全局规则都写在 `body` / `body *` / `::-webkit-scrollbar` 上，没有裸类选择器会命中本面板；设计令牌定义在 `body`，portal 后仍可继承，本组件重绑的 `--dsw-elevation-stroke-color` 亦照常生效（主题层该变量本就按元素声明，`gradient-shadow-text.css`）。
- 定位逻辑本地实现而非扩展 harness 上游 hook：官方 `ModelSelect` 出于同一原因——其源码注释写明该 hook 只从左边缘定位，故官方自己镜像了测量与钳位逻辑（并以 `jscpd:ignore` 标注）。上游改造需改 dsh 仓，按协作规则不入本仓。
- 滚动定位用 `scrollTop` 手算而非 `element.scrollIntoView()`：后者会滚动所有可滚动祖先，面板 portal 到 body 后会把背景页面一并拽动。
