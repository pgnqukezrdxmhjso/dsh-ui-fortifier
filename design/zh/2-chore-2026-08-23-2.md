# 2-chore-2026-08-23-2

## 直接原因

二开环境下工作区依赖版本可能变化，`workspace:^` 无法记录开发时的版本信息。

## 解决方案

- package.json 中除 `@deepseek-ai/dsh-invariants` 外的 `@deepseek-ai/dsh-*` 依赖从 `workspace:^` 改为具体版本号（`0.1.1-rc.2`），`@deepseek-ai/cordis` 改为 `4.0.1`，`@deepseek-ai/schemastery` 改为 `3.18.1`。
- `@deepseek-ai/dsh-invariants` 保留 `workspace:^`（verify-package-invariants 门禁强制）。

## 思路

- 依赖版本号直接记录在 package.json，二开的人可对照 README 的"基于 dsh 版本号 开发"章节匹配工作区版本。
- 发布 npm 时无需 pnpm 转换 workspace 协议。

## 额外收益

- 发布流程简化（依赖已是 npm 版本号）。
