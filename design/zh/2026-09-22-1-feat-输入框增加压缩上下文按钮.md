# 2026-09-22-1-feat-输入框增加压缩上下文按钮

## 直接原因

压缩上下文此前只能手输 `/compact` 指令，输入框没有任何入口。

## 解决方案

在输入框工具行左组（「+」、回形针、模式选择之后）的右端注册一个纯图标按钮。点击先弹出确认气泡，气泡内确认才经 `ctx.remote.commands.execute(sessionId, '/compact', [])` 提交指令；点气泡外或按 Escape 取消。按钮在会话回合运行中与提交等待期间禁用；`mousedown` 阻止默认聚焦，与左组其余按钮一致，点击后光标留在编辑器内。新增 `compact-button` 功能模块，纳入设置页开关。

## 思路

**结论**：复用官方命令通道执行既有 `/compact`；按「手动压缩要求 agent 空闲」这一前提在运行中禁用按钮；因压缩不可撤销，点击先经确认气泡，气泡内确认才提交。

因果链：

- 目标是「效果就和压缩上下文指令一样」。达成该目标有两条路：自行调用压缩能力，或提交那条指令。选后者，因为指令本身就是「和指令一样」的定义——自行调用需要另外复制「无可压缩历史」「忙碌」「摘要失败」等一整套分支行为，任何一处漏掉就不再等价。
- 提交指令需要命令通道。官方已有先例：`ui-plan` 的 Plan 控件正是用 `ctx.remote.commands.execute(sessionId, '/plan off', [])` 离开计划模式，故照此实现，不新增服务、不碰 dsh 仓。
- 由此带来一个额外约束：指令的生命周期由 host 写入会话流（`command/run` / `command/done`），结果作为会话节点呈现，命令面板本身也不回显结果。故按钮只负责提交，不重复呈报成败；若在按钮上再报一次，同一件事会有两个表面。
- 加确认气泡的原因：初版点击即提交，用户反馈「一点就直接压了感觉有点危险，唯一手抖点到了」。压缩会重写会话历史且没有撤销通道，一次误点造成的结果不可逆，故在提交前插入一次显式确认。气泡内容只给一句确认问句与一个确认键，取消走点外部与 Escape，避免为一个小图标按钮引入两个额外控件。文案曾写成后果陈述句（「较早的历史将由摘要替代」），用户指出「弹出框应该是个确认交互的提示」，故改为问句「确认压缩？」并把按钮改为「确认」——陈述句读起来像警告标签，没有在问用户确不确定。
- 禁用运行中的原因：手动压缩要求 agent 空闲（`command-compact` 对忙碌直接返回失败文案）。不禁用的话，用户点一下只会得到一条必然失败的节点，属于把已知会失败的操作留给用户。
- 位置取 `conversation.input.left`：该 list 槽的渲染点就在左组末尾，即「左下角区域的右边」；且此前无占用者，`order: 100` 不与他人排序冲突。
- 图标最终由用户提供：官方图标库没有压缩语义的字形，两次选用官方图标都被读错——`IconApiOutline14`（对话流压缩标记同一字形）是圆角方框内含 `>` 与 `_`，即终端提示符，用户反馈「长的和 ssh 似的」；改用 `IconEnhanceOutline16` 后是四条长短递减的横线，用户又反馈「像文章段落的意思」。两次都错在按图标名或先例选形、没有按实际字形判断。我随后自画「中央横线 + 上下箭头夹向它」，用户评「画的太奇怪」；换成用户给的第一个字形后又因我设成 14px 而「变小了又看不清」，最终采用用户给出的第二个字形并取 16px（官方图标集默认值）。14px 的来源是左组「+」「回形针」用 `size={14}`，但那是为笔画稀疏的图标选的，新字形笔画更密，14px 下细节糊在一起。内联 SVG 有先例：`session-id-copy` 的 `HashGlyph` 即因官方无井号字形而内联，且 `d` 不属文案属性（`scripts/verify-client-ui-i18n.ts` 的 `COPY_ATTRIBUTES` 未收录），门禁不拦。
- 按钮做成可选开关：本插件其余五项功能均为设置页可关模块，`modules` 是 `Record<keyof Config, ModuleEntry>` 强约束，新增模块按既有机制接入即可，无需改动设置页代码。
- 顺带修正开关行顺序：`MODULE_ORDER` 的注释写着「按位置排序」，但实际顺序从加 `session-id-copy` 那次（提交 `4c41cbb`）起就已漂移——标题栏的 `session-id-copy` 被排在输入行两项之后；本次我又在同一处追加 `compact-button`，同样没回头核对。用户指出后改为按界面位置排列：会话标题栏 → 输入行（左组 `compact-button`，右组 `provider-label`、`model-picker`）→ 设置页（`open-dsh-folder`、`settings-frame`）。`README.md` / `README.zh.md` 的功能表原为同一旧序，一并调整。
- 气泡定位必须在开启的同一帧就挂载面板：`useAnchoredPosition` 在该帧读 `panelRef` 量尺寸。初版把 portal 写成 `{open && position && ...}`，首次提交时 `position` 仍为 `null`，面板未挂载，于是高度按 0 计算、`height > 0` 的视口钳位分支被跳过、`ResizeObserver` 也未建立（`panel === null`），修正永不发生，气泡朝下溢出屏幕。改为 `{open && ...}` 且以隐藏的测量位置先挂载（官方 `Menu` 的 `MEASURE_STYLE` 即此用途），量到坐标后再定位。
